# Repair levers: what a failing check on each screen tells the caller to move.
#
# A scorecard that says only "this failed" leaves the caller searching. A repair lever
# names the parameter to move and the direction that improves the margin, and where a
# design inverse exists it names the value that lands the required margin exactly
# (docs/repair-feedback.md). This file records the decision for EVERY public screen, so
# that a screen with no lever is a recorded gap rather than an oversight.
#
# Format: "<module>.<screen> -> <parameter> (solved|directional)" for a screen that emits
# a lever, one line per lever; a bare "<module>.<screen>" for one that emits none yet. A
# screen may appear more than once under `levers` and never in both sections.
#
# THE GATE READS BOTH DIRECTIONS (tests/test_contract.py). Every public screen must appear;
# every recorded lever must actually be constructed by that screen — resolved through the
# module's own call graph, because the hint is usually built in a helper the screen calls;
# every lever a screen constructs must be recorded; and a lever's parameter must be a
# keyword argument of the screen or a field of a model it takes, or it names something the
# caller cannot move.
#
# `solved` and `directional` are not interchangeable. A solved lever claims a value; a
# directional one claims only a sign, which is a claim about the check's shape over its
# whole domain and has to be swept before it is declared. `screen_infinite_slope` carries
# both, and its slope-angle direction is scoped to below 45 degrees because the trend
# reverses above it.
