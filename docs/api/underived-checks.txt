# Checks that ship without a worked derivation (the derivation-coverage ratchet).
#
# `calculation-report`'s "Derivation metadata is part of the check contract" says CI SHALL
# report the coverage ratio and fail when a newly added check ships without metadata. This
# file is the registry that requirement's scenario refers to, and the gate lives in
# tests/conftest.py.
#
# WHAT A LINE IS. A check is keyed by the clause it cites — the same key the effectivity
# ratchet in docs/api/editionless-citations.txt uses, and the same thing a reviewer reads.
# A clause is ANSWERED only when every library-produced scorecard entry citing it has said
# what its arithmetic is. One entry short and the clause is not answered: a clause half
# worked renders a formula for some parts and a bare table for others, which reads as
# though the whole thing was derived.
#
# AN ENTRY ANSWERS IN ONE OF TWO WAYS, and only one of them is a line in this file.
#
#   1. It carries a `Derivation` — the formula, the values put into it, the result.
#
#   2. It carries an `Underived` (anvilate.derivation), which is the check saying on
#      itself that there is no formula here and why. Two kinds, kept apart:
#
#        lookup          no arithmetic between the two numbers — an exemption, an
#                        identification line, a table comparison, a consistency verdict.
#        numeric_result  real mathematics and no substitutable line: the value is the
#                        root of an equation, solved rather than evaluated, so the
#                        inputs table IS its correct rendering.
#
# THIS FILE IS THE THIRD KIND: DEBT. A closed form nobody has written down yet. It is
# unfinished work, the list is downward-only, and it is deliberately not something a check
# can declare about itself — a check that could file its own debt would retire it by
# describing it.
#
# The [lookup] section below is what remains of an earlier design in which every kind was
# keyed by clause. It is kept for clauses whose entries have not yet been given their own
# `Underived`, and it does the same job for them; new declarations go on the entry, where
# the check is. A clause cited by one computing check and one exempt check cannot be
# answered once, and answering it once here was wrong for every check but the first.
#
# The lookup half is enforced mechanically rather than on the honesty of the reason: an
# entry carrying a COMPUTED SAFETY FACTOR may not call itself a lookup, because a lookup
# asserts there is no arithmetic between its two numbers and a factor sitting between them
# disproves it. The type refuses to hold the label, so that debt cannot be relabelled.
#
# `numeric_result` has no such test, and deliberately not: a safety factor can itself be a
# solved quantity — the BS 7910 load-line margin is where a ray meets a bent envelope,
# bisected for — so refusing every declaration beside a factor would refuse real ones. That
# kind rests on its stated reason, and the reason has to say what was solved.
#
# TO PAY A LINE OFF: give every entry the check produces a Derivation, or an Underived
# where it genuinely has no formula, then delete the line from [debt]. Do NOT add a line to
# silence a failure on a new check — a new check ships with its derivation. Do NOT reach
# for [lookup] or an Underived to make a formula stop failing.
#
# Format: one clause per line, then " :: ", then the reason.

[lookup]
ASME BTH-1 §3-1.3 (Design Category) :: the entry is the lifter's identification line — rated load, design load, Category, Service Class. §3-1.3 classifies a device into Category A or B and hands the resulting design factor to every check below it; it computes no margin of its own.
DFM screening estimates (typical finest achievable tolerances) :: the demanded tolerance band is compared with the process floor the capability table records. The table is the whole check; there is no formula between the two numbers.
ASME B30.20 :: a verification-plan item crossed into the characteristic list — a physical proof test with an acceptance criterion and a recorded outcome, not a calculation the library performs.
standards effectivity :: a consistency verdict over the citations a bundle carries — every reference names an edition, and no standard appears at two. No quantity is calculated.

[debt]
AISI S100 Appendix 1 (Direct Strength Method) :: the DSM capacities from the elastic local, distortional and global buckling loads.
Aluminum Design Manual 2020 Part I §B.4/§B.5.4/§E.3/§F.4.2 :: the unwelded and heat-affected capacities and the slenderness limits that select between them.
