# Refusals that state no declaration, and why — the exclusion list for the gate in
# tests/test_needs.py.
#
# A check that could not run should say what it needed, so `anvilate.needs` can tell an
# engineer their next action. Not every refusal has one: some report a capability this
# library has not built, some answer a declaration that IS present, and some are corrections
# rather than gaps — the document said something and it did not resolve, which a needs item
# would misdescribe as a value nobody supplied.
#
# One line per site, `function | entry name | cause`, where a bare function is in
# src/anvilate/screening.py and any other module is named first, `analysis/optomechanics.py:qualify`.
# The gate refuses a NOT_EVALUATED ScorecardEntry that neither carries `needs=` nor appears
# here (outside screening, nor sits under its module's backlog ceiling in tests/test_needs.py),
# and refuses a line here that no longer matches a site. Adding a line is a deliberate act
# with a diff, which is the point: the honest default is that a refusal states its need.
_budget_entries | budget {budget.name} | a correction, not a gap: the budget's contributors bind to checks that are on the card and measured something else, and the fix is the binding the document already wrote
_chain_entries | stack-up chains | a correction: a linked dimension's tolerance designation does not resolve, so the document states a band the tables do not carry
_combination_entry | load combination | a correction: the declared combination basis itself could not be resolved, and the fix is the basis the document already names
_constraint_entries | constraint {field} | a capability gap: max_mass, max_cost and the envelope are bounds on a whole part, and nothing this library builds today weighs, costs or bounds one
_declared_bound_entries | FEA convergence tolerance | a capability gap: the tolerance bounds a T3 run, and T3 is not a synchronous screen
_declared_bound_entries | published interface contracts | a capability gap: a published contract states a mating geometry, and checking it takes built geometry
_dfm_entries | tolerance achievability: {dimension.tag} | a correction: the declared tolerance or fit designation does not resolve, so the document states a band the tables do not carry
_displacement_entry | displacement limit | a capability gap when no check computed a deflection, and an answer when every computed deflection clears the limit; neither is a missing declaration
_envelope_entry | constraint envelope | a capability gap: fitting a part in an envelope takes the whole solid, and a document declares the element its checks need
_geometric_tolerance_entry | geometric tolerance | a capability gap: the remaining Y14.5 rules turn on the tagged feature's type and the zone is checked against built geometry
_min_wall_entry | minimum wall | a correction at one site (a wall that is not a length) and an answer at the other (every declared wall clears the minimum); the third site states its need
_reference_entries | interface resolution: {interface.tag} | a capability gap: the contract is imported from another document, and a screen of one document cannot fetch another
_screen_element | T1 analytical | two correction sites: an element_type the registry does not carry, and a pack screen's own refusal about the element it was given; element_params its model refuses state their missing fields, and the fourth site states its need
screen_spec | T0 geometry | a capability gap: T0 checks a built solid and no geometry is generated from a spec today
screen_spec | T3 FEA | a capability gap: T3 is bounded by a convergence criterion rather than by the size of its input
screen_structure_element | T1 analytical | a correction: a structure cannot be a member of a structure, and the fix is to list its members alongside the others
_keepout_entries | keepout {keepout.tag} | a capability gap: intrusion is measured by intersecting the keepout with the built part, and screening a document builds no geometry, so no declaration would let it run
analysis/optomechanics.py:qualify | entry.name | a capability gap: the screen assumes a uniform soak and the declared condition is a gradient, which no soak screen describes whatever else is declared
analysis/optomechanics.py:athermal_focus | name | a data-coverage limit, not a missing value: the material record states expansion over ranges that do not cover the swing, and the fix is a different record rather than a declaration
analysis/optomechanics.py:cycling_retention_scorecard | name | verification-only by construction: no screen here models drift over repeated cycles, so the entry names its test method and stays open until that test is run
assembly.py:screen_swing_arc | name | a correction: the requirement names a face the build does not tag, and the refusal lists the faces it does, so the fix is the name already written
analysis/pressure_vessel.py:asme_b313_pressure_scorecard | name | three sites that are not gaps: an allowable read at another temperature (a correction of a value supplied), a wall the allowances consume (an answer about the design), and a wall past the t < D/6 scope of the formula (a capability limit); the fourth states its need
callouts.py:callout_scorecard | surface finish at {callout.where} | a capability gap at one site: the attainable-roughness bands are Ra and the callout states another parameter, which no declaration converts; the other site states its need
callouts.py:callout_scorecard | coating at {callout.where} | a capability gap: the entry states the plated size shift, and nothing here takes a fit or thread class to check that shift against
callouts.py:callout_scorecard | heat treatment at {callout.where} | a data-coverage gap at one site: the materials table holds no record for the base material in that condition, which adding a record fixes and no declaration does; the other site states its need
callouts.py:callout_scorecard | process note '{callout.category}' at {callout.where} | a capability gap: a process note is typed and carried, and no check in this library consumes its category yet
analysis/fatigue.py:weld_fatigue_scorecard | name | an answer at one site: a stress range past the EN 1993-1-9 section 8 elastic limit means the detail yields, which the nominal-stress S-N method does not cover and no declaration changes; the other two sites state their needs
analysis/fracture.py:fad_scorecard | name | an answer at one site: an assessment point with no primary load has no load line and no margin, which is a fact about the load rather than a missing value; the other site states its need
analysis/cold_formed_steel.py:dsm_scorecard | {update} | a capability limit: a section outside the AISI S100 prequalified geometry is permitted with a more conservative factor this screen does not apply, and no declaration moves the section inside it
budget.py:to_entry | name | a propagated gap: a budget waits on the checks it sums, whose own entries state what they need, so repeating it here would count one missing value twice
dependency.py:run_chain | name | a propagated gap: the check takes a value an upstream check did not produce, and the upstream's own entry states what it needs
export/qif.py:_verification_entries | verification coverage: {check} | a capability gap: no physical test in the plan's catalogue measures this check, which a declaration cannot add
keepouts.py:_entry | name | a capability gap at one branch (an imported body whose file this build does not read) and a correction at the other (an anchor naming a face the build does not tag, listed in the refusal)
keepouts.py:screen_keepouts | keepout intrusion | a summary: none of the declared keepouts was generated, and each one's own entry says why
loads.py:combination_scorecard | name | an answer at one site: every classified case sums to zero demand under every combination, so there is nothing to screen; the other site states its need
mcp.py:_cancelled_fea_result | T3 FEA | an outcome, not a gap: the task was cancelled, and running it again is the remedy rather than declaring anything
scorecard.py:from_safety_factor | name | three corrections: a NaN requirement, band or factor is an input to fix, not a value nobody supplied; the fourth site passes its caller's `needs=` through
standards/effectivity.py:design_basis_scorecard | name | a correction at one site: a pinned standard that no citation names is a pin to remove or a citation to add, and the refusal names which; the other two sites state their needs
